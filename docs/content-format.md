# صيغة ملفات الأسئلة

**الإصدار:** 0.1 · 2026-10-23 · **الحالة:** مسودة بانتظار مراجعة الكاتب
**كتبها:** المهندس · **يملك الملفات:** الكاتب (`content/`)، والمالك يعدّل `content/wheel.json`

هذه الصيغة يكتب بها الكاتب البنك كله، وتقرؤها اللعبة كما هي. الأمثلة الكاملة في `docs/content-examples/`، وهي بالبنية نفسها التي سيأخذها `content/`.

---

## 1. بنية المجلد

```
content/
├── packs/
│   ├── index.json            ← قائمة الحزم
│   └── general/              ← الحزمة الثقافية العامة (مجلد لكل حزمة)
│       ├── pack.json         ← اسم الحزمة والأنماط المستثناة
│       ├── letter.json       ← الحرف المعيّن (ومعه أسئلة كسر التعادل)
│       ├── last-two.json     ← آخر حرفين
│       ├── auction.json      ← المزاد
│       └── ranking.json      ← الترتيب
└── wheel.json                ← تحديات العجلة وخانات الحظ (لكل الحزم)
```

- **ملف أسئلة لكل نمط** في كل حزمة. واسم الملف هو معرّف النمط، فلا يُغيَّر.
- **حزمة جديدة** = مجلد جديد بالبنية نفسها، ويُضاف معرّفه إلى `index.json`.
- **نمط تستثنيه الحزمة** لا يحتاج ملفاً، ولا يظهر في اختيار الأنماط حين تُلعب.

## 2. قواعد عامة لكل الملفات

| القاعدة | التفصيل |
|---|---|
| الصيغة | JSON بترميز UTF-8. الأسماء (المفاتيح) بالإنجليزية كما هي هنا حرفاً بحرف، والقيم بالعربية |
| الأرقام | **إنجليزية** في كل نص (1% لا ١٪). الفاحص يرفض الأرقام الهندية |
| المعرّف `id` | فريد في البنك كله، بحروف إنجليزية صغيرة وأرقام وشرطات. الصيغة المقترحة: `<الحزمة>-<النمط>-<رقم من 3 خانات>`، مثل `general-letter-007`. **لا يُغيَّر بعد النشر**، لأن ذاكرة الأسئلة المستعملة تعتمد عليه |
| المستوى `level` | `easy` (سهل) · `medium` (متوسط) · `hard` (صعب). والترتيب `easy` و`hard` فقط |
| المجال `domain` | واحد من الثمانية في الجدول أدناه |
| رقم الصفحة `page` | **اختياري**، للحزم الدراسية: رقم صفحة الكتاب الذي أُخذ منه السؤال |
| حقل غير معروف | يرفضه الفاحص، ليكشف الأخطاء الإملائية في أسماء الحقول (مثل `anwser`) |

**المجالات (القسم 6.3):**

| `domain` | المجال |
|---|---|
| `kuwait-gulf` | الكويت والخليج |
| `geography` | الجغرافيا |
| `history` | التاريخ |
| `religion` | الدين (في حدود المتفق عليه) |
| `language` | اللغة والأدب |
| `science` | العلوم والطبيعة |
| `sports` | الرياضة |
| `daily-life` | الحياة اليومية |

## 3. ملفات الحزمة

### `packs/index.json`
```json
{ "packs": ["general"] }
```

### `packs/<الحزمة>/pack.json`
| الحقل | معناه |
|---|---|
| `id` | معرّف الحزمة، **يطابق اسم مجلدها** |
| `name` | الاسم الذي يراه المقدّم في الإعداد |
| `description` | سطر وصف (اختياري) |
| `excludeModes` | الأنماط المستثناة، من: `letter` · `last-two` · `auction` · `ranking`. فارغة `[]` إن لم تستثنِ شيئاً. ويجب أن يبقى نمطان على الأقل |

## 4. الأنماط

### 4.1 الحرف المعيّن · `letter.json`
```json
{
  "mode": "letter",
  "questions": [
    { "id": "general-letter-001", "level": "easy", "letter": "ش",
      "prompt": "ما تبحث عنه حين يقول هاتفك: البطارية 1%", "answer": "شاحن", "domain": "daily-life" }
  ]
}
```
| الحقل | معناه |
|---|---|
| `letter` | حرف عربي واحد، يظهر في مربع الحرف |
| `prompt` | المطلوب، كما يُعرض للجمهور |
| `answer` | الإجابة النموذجية، يراها المقدّم وحده |
| `tiebreak` | `true` لأسئلة **كسر التعادل** الاحتياطية (صعبة فقط). تُحفظ في الملف نفسه، ولا تظهر في الجولات العادية. ويُحذف الحقل في غيرها |

البنك: 20 لكل مستوى، و20 صعبة لكسر التعادل.

### 4.2 آخر حرفين · `last-two.json`
```json
{ "id": "general-last-two-001", "level": "easy", "ending": "ان",
  "prompt": "صغير الحجم، لكنه يُكرَم به الضيف في كل بيت كويتي", "answer": "فنجان", "domain": "kuwait-gulf" }
```
| الحقل | معناه |
|---|---|
| `ending` | الحرفان **دون تطويل**: `"ان"` لا `"ـان"`. اللعبة تضيف التطويل عند العرض |
| `prompt` · `answer` | كالنمط الأول. وأي كلمة أخرى تنطبق تُقبل بحكم المقدّم |

القائمة داخل `"questions": [ ... ]` كالنمط الأول. البنك: 20 لكل مستوى.

### 4.3 المزاد · `auction.json`
```json
{
  "mode": "auction",
  "topics": [
    { "id": "general-auction-001", "level": "easy", "topic": "فصول السنة", "domain": "science",
      "items": [ { "name": "الربيع" }, { "name": "الصيف", "alts": ["القيظ"] }, { "name": "الخريف" }, { "name": "الشتاء" } ] }
  ]
}
```
| الحقل | معناه |
|---|---|
| `topic` | الموضوع كما يُعرض للجمهور |
| `items` | **القائمة المرجعية كاملة**: كل عنصر يظهر زراً في نافذة المقدّم ينقره حين يُذكر |
| `items[].name` | الاسم الأشهر للعنصر |
| `items[].alts` | صيغ بديلة مقبولة للعنصر نفسه (اختياري). تظهر للمقدّم بجوار الاسم ليعرفها |

الفاحص يرفض تكرار عنصر بصيغة أخرى (مثل «الاثنين» و«الإثنين» عنصرين). البنك: 10 لكل مستوى.

### 4.4 الترتيب · `ranking.json`
```json
{
  "mode": "ranking",
  "lists": [
    { "id": "general-ranking-001", "level": "easy", "domain": "sports",
      "title": "الدوري الإنجليزي · الترتيب النهائي لموسم 2025–2026", "asOf": "2026-05",
      "items": [ { "rank": 1, "name": "..." } ],   ← مختصر هنا: 13 عنصراً في الملف الحقيقي
      "sources": [
        { "title": "...", "url": "https://...", "accessed": "2026-10-23" },
        { "title": "...", "url": "https://...", "accessed": "2026-10-23" } ] }
  ]
}
```
| الحقل | معناه |
|---|---|
| `title` | عنوان القائمة **بتاريخها** كما يُعرض. والفاحص يتحقق أن سنة `asOf` مذكورة فيه |
| `asOf` | تاريخ القائمة: `2026` أو `2026-05` |
| `items` | **13 عنصراً بالضبط** مرتبة: 1 إلى 10 الخانات الظاهرة، و11 و12 و13 الفخاخ. `rank` يساوي الترتيب |
| `items[].alts` | صيغ بديلة (اختياري) كالمزاد |
| `sources` | **مصدران على الأقل** متطابقان في الترتيب، لكل منهما عنوان ورابط كامل وتاريخ اطلاع. والمدقّق يطابقهما |

البنك: 10 سهلة و10 صعبة.

## 5. العجلة · `wheel.json`
```json
{
  "challenges": [ { "id": "wheel-001", "text": "نص التحدي كما يُعرض" } ],
  "luck": [
    { "effect": "lose-3", "label": "خصم 3 نقاط" },
    { "effect": "steal-3", "label": "اسرق 3 نقاط من خصمك" },
    { "effect": "gift-3", "label": "هدية: +3 نقاط" }
  ]
}
```
- `challenges`: سبعة تحديات أدائية، ملتزمة بالمحظورات (لا إحراج ولا أذى).
- `luck`: ثلاث خانات ثابتة التأثير. يجوز تغيير `label` (النص الظاهر)، ولا يُغيَّر `effect` لأنه ما تنفّذه اللعبة. والقيم نفسها (3 نقاط) مبدئية لا تُغيَّر قبل الشريحة 8.

## 6. الفاحص

قبل كل رفع إلى `content/`، يُشغَّل:

```
node tools/validate-content.mjs content
```

يطبع الأعداد مقابل المطلوب للبنك الكامل، ثم **التنبيهات** (لا تمنع، يراجعها الكاتب بعينه، مثل إجابة لا تبدأ بالحرف المعيّن)، ثم **الأخطاء** (تمنع). والنتيجة الأخيرة «سليم» أو «فشل». واللعبة ستستعمل الفاحص نفسه عند التحميل.

## 7. طلب مراجعة الكاتب

أرجو من الكاتب أن يراجع الصيغة كلها، ويجيب في سجله عن هذه النقاط تحديداً، أو يكتب ما يحتاج تغييره في `docs/open-questions.md`:

1. **إجابة واحدة نموذجية** للحرف المعيّن ولآخر حرفين: هل تكفي، أم تحتاج حقلاً لإجابات نموذجية أخرى يراها المقدّم؟
2. **الصيغ البديلة** (`alts`) في المزاد والترتيب: هل تكفي قائمة بسيطة لكل عنصر؟
3. **أسئلة كسر التعادل** داخل `letter.json` بعلامة `tiebreak`، لا في ملف مستقل. هل يناسبك ذلك؟
4. **`ending` دون تطويل**، واللعبة تضيفه. هل يلزم أن يُعرض بغير التطويل أحياناً؟
5. **المعرّفات** بالإنجليزية بصيغة `general-letter-001`. هل الترقيم بثلاث خانات يكفي؟
6. هل تحتاج حقلاً للملاحظات الداخلية (لا تُعرض)، كسبب قبول إجابة ما، أو تنبيه للمدقّق؟

**علامة اعتماد الصيغة:** يوافق الكاتب عليها أو تُعدَّل بملاحظاته، ثم يكتب أول ملف حقيقي بها في `content/` فيمرّ على الفاحص «سليم».
